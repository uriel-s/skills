Generate and verify the project toolchain contract (`.claude/checks.sh`) for a Python project. $ARGUMENTS

/dev and /work depend on `.claude/checks.sh` with subcommands `test | lint | security | all`.
This command creates it, verifies it runs, and checks the project's CLAUDE.md. Run it once per
project, before the first /dev run.

## Step 1: Discovery

- Confirm this is a Python project (`pyproject.toml`, `setup.py`/`setup.cfg`, or
  `requirements*.txt`). If not → STOP and report; this command is Python-only by design.
- Detect the source layout: `src/<pkg>/`, a top-level package dir, or flat. Detect the test
  dir (`tests/`, `test/`).
- Detect available tools: is `ruff` importable/installed? `bandit`? (`python -m ruff
  --version`, `bandit --version`). Note what's missing.

## Step 2: Generate `.claude/checks.sh`

If the file already exists: show its content and ask whether to overwrite (the only permitted
prompt). If it carries the generated-by stamp and is identical to what would be generated,
report "up to date" and skip.

Write this template with `<SRC>` and `<TESTS>` resolved to the ACTUAL detected paths:

```bash
#!/usr/bin/env bash
# generated by /setup-project — toolchain contract for the Claude command system
# subcommands: test | lint | security | all   (exit 0 = green)
set -u
cmd="${1:-all}"

run_test()     { python -m pytest; }
run_lint()     { python -m ruff check <SRC> <TESTS>; }
run_security() {
  if command -v bandit >/dev/null 2>&1; then
    bandit -q -r <SRC>
  else
    echo "WARN: bandit not installed — security check skipped"
  fi
}

case "$cmd" in
  test)     run_test ;;
  lint)     run_lint ;;
  security) run_security ;;
  all)      run_lint && run_security && run_test ;;
  *)        echo "usage: checks.sh [test|lint|security|all]"; exit 2 ;;
esac
```

Create the `.claude/` directory if missing. If `ruff` is not installed, still generate the
script but WARN prominently in the report — `lint` will fail until it's installed.

## Step 3: Verify

Run `bash .claude/checks.sh all` and report the result honestly. Failing tests are the
project's current state, not yours to fix here — report them; do not modify project code.

## Step 4: CLAUDE.md check

If the project root has no CLAUDE.md, or it is empty: warn that /work's quality depends on a
real CLAUDE.md (development workflow, conventions) and suggest running /init. Do not create or
edit CLAUDE.md yourself.

## Step 5: Report

```
Created/updated: .claude/checks.sh   (or "up to date" / "skipped by user")
Detected: src=<SRC> tests=<TESTS> ruff=<yes/no> bandit=<yes/no>
Verification: checks.sh all → <green / red: which stage failed>
CLAUDE.md: <ok / missing / empty — suggested /init>
```

## Rules

- Do NOT modify any files besides `.claude/checks.sh`.
- Do NOT fix failing tests or lint during Step 3 — report only.
- The only permitted prompt is the overwrite confirmation in Step 2.
