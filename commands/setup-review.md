Install project-specific `/review` and `/ui-test` commands from the master templates. $ARGUMENTS

## How this works

The master command files live in `~/.claude/commands/` (`review.md`, `ui-test.md`). This
command does NOT generate a review process from scratch — it INSTALLS the master into the
project's `.claude/commands/`, prepends a version stamp, and appends a generated "Project
parameters" section so the installed copy skips rediscovery. One source of truth; no forked
templates; `/setup-review` can later detect when an installed copy is older than the master.

## Instructions

### Step 1: Project Discovery

Detect everything automatically — no discovery questions (the only permitted prompt is the
overwrite confirmation below).

**Find these:**
- **Tech stack & framework** — read `pyproject.toml`, `package.json`, `Cargo.toml`, `go.mod`,
  or equivalent. Identify the language(s), framework(s), and package manager.
- **Architecture docs** — search for `ARCHITECTURE.md`, `CONTRIBUTING.md`,
  `docs/architecture*`, `docs/design*`, `docs/code-review*`.
- **Coding guidelines** — search for `CLAUDE.md`, `.editorconfig`, linter configs, style guides.
- **Test patterns** — find test files, identify framework (pytest, jest, vitest, etc.) and
  naming conventions.
- **Main branch** — `git symbolic-ref --short refs/remotes/origin/HEAD` (strip the `origin/`
  prefix); if unset (e.g., no remote), fall back to local `main`, then `master` — first
  existing wins. If neither exists, use the currently checked-out branch and note that in the
  report.
- **Project structure** — note directory layout and architectural pattern (layered, MVC,
  monolith, etc.).
- **UI layer** — PySide6/PyQt/tkinter/React/Vue/Svelte/Angular imports; UI file locations,
  style definition files, UI tests + exact runner command.

For **fullstack/monorepo** projects: identify each part separately (e.g., "React frontend in
`client/`, FastAPI backend in `server/`").

### Step 2: Install `.claude/commands/review.md`

1. Locate the master at `~/.claude/commands/review.md`. Missing → **STOP and report**: "Master
   review.md not found in ~/.claude/commands — deploy the commands repo first." (A failure
   report, not a question.)
2. Compute the master's SHA-256; use the first 12 hex chars as `<hash>`.
3. If `.claude/commands/review.md` already exists in the project:
   - Has a version-stamp line with the same `<hash>` → report "already up to date", skip
     (unless `$ARGUMENTS` contains `--force`).
   - Has a stamp with a different hash → warn "installed copy is from an older master" and ask
     whether to overwrite.
   - Has no stamp (hand-written or legacy generated copy) → warn and ask whether to overwrite.
4. Write the installed file as, in order:
   1. Stamp: `<!-- installed by /setup-review from master review.md @ <hash> on <YYYY-MM-DD>. Do not hand-edit; rerun /setup-review to update. -->`
   2. The master content, **verbatim** — do not edit, trim, or "improve" it.
   3. Appended section:

      ```
      ## Project parameters (generated by /setup-review)

      Discovery shortcut — found at install time. Re-verify cheaply instead of searching from
      scratch; if the project has drifted, trust what you find over this list.

      - Trunk branch: <detected>
      - Guideline docs: <actual paths found, or "none">
      - Architecture docs: <actual paths, or "none">
      - Review template: <path if docs/code-review-template.md or similar exists, else "none">
      - Tests: <framework>, <test dir>, naming <pattern>
      - Framework-specific checks for Agent 3: <tailored list — e.g. PySide6: QSS compliance,
        signal/slot usage, GUI-thread blocking, QTimer/QThread cleanup; React: hook rules,
        re-render optimization, key usage; Django: N+1 queries, migration safety; Go:
        goroutine leaks; Rust: ownership patterns>
      ```

   Every line must reference actual paths found in Step 1 — no `{{placeholder}}` may survive
   into the written file.

### Step 3: Install `.claude/commands/ui-test.md`

Only if Step 1 detected a UI layer; otherwise skip and note "No UI layer detected — skipping
/ui-test". Same mechanism as Step 2 with the master at `~/.claude/commands/ui-test.md`: stamp,
verbatim master content, appended `## Project parameters (generated by /setup-review)` section
with: UI framework, UI file paths, style definition files, UI test dir + the exact runner
command (e.g. `python -m pytest tests/ui/ -v --tb=short`).

### Step 4: Report

```
Installed:
- .claude/commands/review.md   @ <hash>  (installed / updated from <old-hash> / up to date / skipped)
- .claude/commands/ui-test.md  @ <hash>  (same, or "skipped — no UI layer detected")

Detected:
- Stack: [language + framework]
- UI Framework: [PySide6 / React / Vue / none]
- Architecture: [pattern or "not documented"]
- Guidelines: [docs found or "none — using defaults"]
- Tests: [framework] ([count] test files)
- Main branch: [branch]

Available commands:
- /review — full code review (project-tuned)
- /ui-test — UI/UX quality check (project-tuned)
```

## Rules

- No discovery questions — auto-detect everything. The ONLY permitted user prompt is the
  overwrite confirmation (Step 2.3 / Step 3).
- A missing master file is a STOP-and-report, not a question.
- Do NOT modify any files besides `.claude/commands/review.md` and
  `.claude/commands/ui-test.md`. Create `.claude/commands/` if it doesn't exist.
- Never edit the master content during install — all project-specific material goes in the
  appended parameters section only.
